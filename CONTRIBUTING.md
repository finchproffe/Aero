# Contributing to Aero

Aero is pre-alpha. Small, reviewable changes are preferred over large rewrites.

## Before coding

- Search existing issues before opening a new one.
- Open a feature proposal for changes to architecture, privacy defaults, storage, or network behavior.
- Never add telemetry, remote configuration, sponsored content, or automatic account creation without an explicit public design decision.

## Pull requests

- Keep one logical change per pull request.
- Explain the user-visible behavior and security impact.
- Add or update tests when the core logic changes.
- Do not commit generated binaries, WebView2 profile data, secrets, certificates, or personal browsing data.
- Use clear commit messages.

## Security

Do not publish exploitable security details in a normal issue. Enable GitHub private vulnerability reporting before the repository becomes public and document the final security contact in `SECURITY.md`.
